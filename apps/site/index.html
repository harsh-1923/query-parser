Use It in Your Code

Describe your product's filters once. Names resolve through your own directory, and anything unclear comes back as an issue, never a guess 

import { createParser, directorySource, ruleTaggerFor } from "@qp/core"
import { schema, toSearchParams } from "@qp/adapter-xyne-spaces"

const parser = createParser({
  schema,
  tagger: ruleTaggerFor(schema),     // the model replaces this in M4
  sources: { person: directorySource(users, { fields, self }) },
})

const r = parser.parseSync("pdfs from utkarsh last week", {
  reference: new Date(), timeZone: "Asia/Kolkata",
})
toSearchParams(r) // type=files&from=u_001&after=…&before=…&q=pdfs

A Small Experiment. Still Growing

What runs here is the M2 rule baseline: hand-written rules tag each part of the query, the product's schema maps them to filters, and a fictional directory resolves names. A tiny trained model replaces the rules in M4.

On 205 test queries the rules reach 69.5 span F1 (results). The time normalizer gets every test time phrase right and 84.9% of a held-out set, with zero wrong answers (S4). Expect mistakes, especially names without "from" or "by".
